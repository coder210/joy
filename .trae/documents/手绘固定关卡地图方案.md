# 手绘固定关卡地图方案（替换程序化 BSP 随机地图）

## Context（背景与目标）

当前 `project_proxy3d` 的 3D 地图由程序化 BSP 随机生成（`procedural_map.h`），玩家出生/障碍/敌人出生点全部依赖随机流与派生 seed。用户希望**地图不再随机生成，改为自己主动编辑**——每一关一张手绘 ASCII 网格（固定关卡，求生之路式）。目标：地图数据静态、跨端完全确定、可自由编辑；同时兼容"关卡选择"（每关=一张手绘图，可定起始关卡）。

已探明关键事实（决定接线方式）：
- 运行时寻路可通行性来自 `pf_build_walkable`（`shared\systems\pathfinding_system.h:30`）**从障碍实体扫描重算**，并非 `PmLayout.walkable` → 后者只是参考副本，可安全替换。
- 敌人出生格/类型只在 `wave_prepare_enemies`（`wave_system.h`）一次性写进 `WaveAdvanceComponent.tiles/si`，`wave_spawn_system` 分帧消费 → 只需换 `tiles` 来源。
- 障碍实体 ID 从 10000 起、按 `layout.obs[]` 顺序自增（`spawn_obstacles_system.h:15`）→ 手绘图必须用**固定扫描序**填 `obs[]` 才能跨端 ID 一致。
- 玩家位置由 `join.position_x/z` 决定（`input_consume_join_system.h`），客户端直接用服务端快照 → 只需改服务端/单机三处出生点。
- `gs.map_seed` 目前只被敌人 `si` 公式与调试用 → 可复用为"每关常量"。

---

## 1. 手绘地图数据格式（新增 `shared\systems\level_maps.h`）

与 2D 版 `map_def.h` 同范式：头文件内置每关 ASCII 网格 + 敌人数量表 + 一个解析函数，`#include "procedural_map.h"` 复用 `PmLayout`。

**图例（每关固定 20 行 × 20 列，与 `PF_GRID_N` 一致）**

| 字符 | 含义 | 行为 |
|---|---|---|
| `#` | 墙 | 碰撞，生成 1×1 PmObstacle |
| `.` | 空地 | 可通行 |
| `P` | 玩家出生 | 可通行；全图**恰 1 个**（缺省报错） |
| `E` | 敌人出生 | 可通行；可多个 |
| `W` | 整柱/高墙 | 同 `#`（选做扩展） |
| `D` | 装饰 | 不碰撞、不生成障碍（选做） |

第一/末行、第一/末列必须是整圈 `#`（保证边缘封闭）。

**坐标映射（纯整数，已核对 `pf_world_to_grid`/`pf_grid_to_world`）**
```
行 r(0..19) → gz = r - 10      列 c(0..19) → gx = c - 10
格子中心世界坐标: x = gx - 9.5, z = gz - 9.5   (即 gx=gz=0 → 世界 -9.5)
PmObstacle: x10 = gx*10 - 95   z10 = gz*10 - 95   hx10 = hz10 = 5（半 0.5m）
            sy10 = 14（墙高 1.4m，落在 PM_HEIGHT_MIN..MAX）   gw = gh = 1
walkable[gz*20+gx] = (ch=='#') ? false : true
```

## 2. 解析函数（`level_maps.h` 内，核心=纯整数+固定扫描序+无随机）

```cpp
static bool level_build_layout(int level, PmLayout* out_obs,
                               int& player_cell,            // 格子索引，-1=缺失
                               int* enemy_cells, int& enemy_n); // 扫描序 E 列表
static int  level_index_for_wave(const GlobalState& gs);    // clamp(gs.level,1,LEVEL_COUNT)
```
- 按 `r` 外、`c` 内（**行主序**）遍历，对每个 `#` 依序填 `layout.obs[count++]`；顺带收集 `P`（恰一个）与 `E` 列表（保持扫描序）。
- 障碍顺序固定 → 实体 ID 跨端一致（确定性关键，必须写注释）。
- 不调用任何 `jpm_*`，不依赖 `ctx->random`。
- 非法字符按 `.` 处理；越界按 `#`。

**敌人数量表**：`inline constexpr int LEVEL_ENEMY_COUNT[LEVEL_COUNT] = { 2, 3, 4, 5 };`（每值 ≥ `ENEMY_SPAWN_COUNT=2` 保证双类型各一只，≤ `WAVE_MAX_ENEMIES`）。

## 3. 替换点：`wave_system.h`

**首波物化**（原 `wave==1` 的 `pmap_generate(ctx->random,&layout)` + `spawn_obstacles_from_layout`）改为：
```cpp
if (gs.wave == 1) {
    PmLayout layout; int pc; int ecell[WAVE_MAX_ENEMIES]; int en;
    level_build_layout(level_index_for_wave(gs), &layout, pc, ecell, en);  // 容错：缺 P/E 则告警
    gs.map_seed = level_index_for_wave(gs);        // 每关常量作 seed，si 公式保持确定
    int oid = 10000;
    spawn_obstacles_from_layout(registry, ctx, layout, oid);   // 不变
    gs.map_wave_generated = gs.wave;
}
```
**敌人出生格**（`wave_prepare_enemies`）：删除 `pm_sample_open_tiles`（不再随机采样）。改为从该关 `E` 列表确定性取：
```cpp
int count = LEVEL_ENEMY_COUNT[level_index_for_wave(gs)];
int start = (gs.wave - 1) % ecn;             // ecn>0
for (int i = 0; i < count; i++) tiles[i] = ecell[(start + i) % ecn];   // 波次旋转+循环取
for (int i = 0; i < count; i++)              // si 保持现有确定性公式（双端同表→同结果）
    si[i] = (i < ENEMY_SPAWN_COUNT) ? i : ((int)gs.map_seed + gs.wave*7 + i*13) % ENEMY_SPAWN_COUNT;
```
`tiles` 来源从"随机洗牌采样开放格"换成"固定 E 列表"，完全确定。`wave_spawn_system` 零改动（`WaveAdvanceComponent.tiles/si` 后续照旧消费）。若 `wave_prepare_enemies` 不再需要 `PmLayout` 形参，需同步改 `wave_spawn_system.h` 调用签名。

## 4. 玩家出生接线（三处）

已有位置由 join 决定，改为该关 `P` 格，纯定点 `pf_grid_to_world(pc % PF_GRID_N)` / `pf_grid_to_world(pc / PF_GRID_N)`：
- `server.cpp`：`handle_cmd_player_join` 的随机出生段 → `P` 格；（Host 本地注入）同改。
- `client.cpp`：单机注入同改。
- 服务端快照自动带 `position_*` 给客户端 → **客户端位置逻辑无需改**。

## 5. 与"关卡选择/起始关卡"衔接

- `GlobalState`（`shared\components\global_state_component.h`）新增 `int start_level = 1;` 与 `int level = 0;`（当前关）。
- `Context` 新增 `selected_level`（跨场景保留，类比 `selected_char_id`）；游戏初始化 `gs.start_level = clamp(ctx->selected_level,1,LEVEL_COUNT); gs.level = gs.start_level;`。
- **联机必须权威端下发**：`start_level` 纳入 `pack_s2c_loading` 与 `pack_s2c_map_reload`，客户端在 `handle_loading`/MAP_RELOAD 覆盖（客户端本地自选不生效，防 MISMATCH）。
- `wave_system` 推进处同步 `gs.level = level_index_for_wave(...)`，使"从第 N 关开始"退化为 wave 时序里对象是第 N 张图。

## 6. 帧同步与 checksum

- checksum 指纹来自 `IdComponent+LogicPositionComponent`（玩家+敌人+障碍）。手绘图为**纯静态表**、双端同一解析序 → 障碍 `(id,x,y,z)`、敌人出生、玩家 `P` 逐位一致，无随机 → **不改 checksum 公式**。
- 顺序保证（关键）：障碍与 E 列表必须用同一"行主序"扫描，否则实体 ID/出生顺序分叉 → MISMATCH。

## 7. 验证

- **单机逐关**：`Context.selected_level=1..LEVEL_COUNT` 进游戏，确认 ①`P` 处出生可移动；②`E` 处刷出 `LEVEL_ENEMY_COUNT` 只敌人且沿 `pf_build_walkable` 可通行；③墙完整、无敌重叠卡死（看 debug_layer 的 walkable）。
- **布局自检（内联 assert）**：每关 `P` 恰一、`E≥1`；复用 `pm_rasterize`/镜像 BOX 分支验证每个 `P/E/.` 在"盒+pad"栅格化后仍可通行；`pm_bfs`（`procedural_map.h:110`）断言所有开放格同属一个连通分量、`P` 可达面积达标。
- **联机双端**：Host/Server + Client 各一，打同关卡，退出后 `diff checksum_log_server.txt checksum_log.txt`（`game_scene.cpp:169-182`），确认无 MISMATCH、实体集合一致；切第 N 关再验。
- **回归**：`wave_spawn_system` 分帧生成、`enemy_take_dead` 复用池、`MAP_RELOAD` 换波路径实测一遍（仅换 tiles 来源，逻辑未动）。

## 8. 风险与容错

1. **1 格宽通道实际不可通行**（已验证）：`pf_build_walkable` BOX 分支用 `半宽0.5 + pad0.6 = 1.1m`，单格墙会封掉自身 + `+x`/`+z` 相邻格。→ 两墙之间至少留 **2 格以上空地**，否则通道视觉通、敌人走不了。图例须写明 + 走自检断言兜底。
2. **start_level 不同步**是唯一新增 MISMATCH 来源 → 必须权威下发、客户端禁止本地覆盖。
3. **缺 P/E / 非法字符**：clamp+容错，缺 P/E 则 log 告警并退到最后可加载关卡（**不许随机兜底**）。
4. **多人出生重叠**：多人 join 都落同一 `P` 会重叠；如需多人可提供多个 `P`（每 conv 依次取，缺则循环）。
