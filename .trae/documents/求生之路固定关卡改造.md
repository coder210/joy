# 求生之路式固定关卡改造

## Context（背景与目标）

当前 `project_proxy3d` 是**无限求生波次**玩法：敌我清空即 `wave++`，无限循环、无通关终点、玩家死后无限复活。用户希望改成**求生之路/左4死（L4D）式的固定关卡**：有限关卡、逐关推进、清完最后一关即通关。

用户明确要求：**先给方案、不要直接改代码**；对"死亡重开/地图来源"等细节倾向于简单，不希望被复杂分支打扰。

关键事实（已探明）：现有代码障碍只在 `wave==1` 物化一次（[wave_system.h](file:///e:/c++/joy/project_proxy3d/shared/systems/wave_system.h#L162-L168)），后续波障碍不变；`handle_map_reload` 客户端也不重建障碍。因此"单张固定地图"已经是现状事实——本改造重心是：**有限关卡数 + 通关胜利信号 + 地图 seed 固定化 + HUD 关卡/胜利展示**，改动面小、对帧同步 checksum 影响最低。

采用推荐方案：**单张固定地图 + 有限关卡 + 通关后停止**。（"每关换新地图"改动量大且 A* 缓存失效易穿墙，列为本期不做、可后续追加。）

## 具体改动（按步骤）

### 1. 关卡常量 —— [spawn_def.h](file:///e:/c++/joy/project_proxy3d/shared/systems/spawn_def.h)
在 `wave_enemy_count` 旁新增（共享常量，双端一致）：
```cpp
inline constexpr int LEVEL_COUNT      = 4;    // 固定关卡数
inline constexpr int LEVEL_MAP_SEED   = 12345; // 固定地图 seed
```

### 2. 通关标志 —— [global_state_component.h](file:///e:/c++/joy/project_proxy3d/shared/components/global_state_component.h)
`GlobalState` 在 `kills` 旁加：`bool victory = false;`（纯状态，不新增实体，不影响 checksum —— checksum 只含 Id+LogicPosition 实体）。

### 3. 胜利判定 + map_seed 固定化 —— [wave_system.h](file:///e:/c++/joy/project_proxy3d/shared/systems/wave_system.h#L140-L195)
- 函数顶部守卫：`if (gs.victory) return;`（防重复广播）。
- 在 `wave_done` 为真、无 pending `WaveAdvanceComponent` 之后、`gs.wave++`**之前**插入：
  ```cpp
  if (gs.wave >= LEVEL_COUNT) {            // 清完最后一关
      gs.victory = true;
      if (ctx->net_server) {
          int frame_id = registry.ctx().get<NetComponent>().frame_id;
          ctx->map_reload_data = pack_s2c_map_reload(frame_id, gs.wave, 1);
      }
      return;                              // 不再 ++wave，不再生成敌人
  }
  ```
- `wave==1` 分支改为固定 seed（去掉消耗共享随机流）：
  ```cpp
  gs.map_seed = LEVEL_MAP_SEED;
  pmap_generate_seed((uint32_t)gs.map_seed, &layout);   // 复用 pmap_generate_seed（procedural_map.h:125）
  ```
  `ctx->random` 保留分配但无需再消费，无需删除。

### 4. 协议加胜利信号 —— [protocol.h](file:///e:/c++/joy/project_proxy3d/shared/protocol.h)
- `pack_s2c_map_reload(int32_t frame_id, int32_t wave, int32_t victory)`：载荷追加第 3 元素（[protocol.h:230](file:///e:/c++/joy/project_proxy3d/shared/protocol.h#L230)）。
- `unpack_map_reload(data,len,frame,wave)` 新增可选出参 `victory`（`array size>=3` 再读，未知旧包默认 0）。
- `pack_s2c_loading`（protocol.h:199）尾部追加 `victory`；`unpack_loading`（protocol.h:334）可选读（`size>=8` 才读），用于中途加入/重连对齐通关态。

### 5. 客户端应用 —— [client.cpp](file:///e:/c++/joy/project_proxy3d/client.cpp) & [context.h](file:///e:/c++/joy/project_proxy3d/context.h#L291)
- `context.h` 的 `PendingMapReload` 加 `int victory = 0;`。
- `handle_map_reload(ctx, wave, victory)`：置 `gs.wave = wave;`；若 `victory==1` → `gs.victory = true` 且**不创建** `WaveAdvanceComponent`（无下一关，不再刷敌）；否则维持现有逻辑。
- 帧对齐调用点（client.cpp:441-445）把 `PendingMapReload.victory` 一并传入 —— 与换波同链路帧同步应用，双端同一帧置标志。
- `handle_loading` 读 `victory` 并写 `gs.victory`。

### 6. HUD：关卡 + 通关横幅 —— [debug_layer.cpp](file:///e:/c++/joy/project_proxy3d/layers/debug_layer.cpp)
- 波次大字：`Wave %d` 改为 `Level %d/%d`（用 `gs.wave` 与 `LEVEL_COUNT`，需 include `spawn_def.h`）。
- 进来提示：`Level N 即将来袭`。
- 新增：`gs.victory` 时绘制中央"通关 Victory"横幅，并抑制普通 Wave/换波提示与（可选）重生倒计时面板。

## 帧同步确定性要点

- `wave_system` 仅权威端（`!ctx->is_authority return`，wave_system.h:142），**客户端不能重算胜利**。胜利信号走权威端 → MAP_RELOAD 帧对齐下发，与换波同一机制，双端同一逻辑帧置标志 → 确定性成立。
- 单机/房主本地即权威端，`gs.victory` 直接写本地 ECS，不走网络也一致。
- 胜利路径不 `create/destroy` 任何实体，只写 `GlobalState` 标量 → 不影响实体 ID 计数与 checksum 校验顺序。
- map_seed 固定化后，双端 `wave_prepare_enemies` 用同一 `gs.map_seed` 采样 → 敌人出生逐位一致。

## 敌方强度递增

直接复用 `wave_enemy_count(wave)`（spawn_def.h：关 1=min2、逐关+1、封顶 8），零改动。需要更陡曲线可后续换关卡查表 `LEVEL_ENEMY_COUNT[LEVEL_COUNT]`。

## 验证 / 回归

1. **单机通关**：`--mode single`，清空第 1 关 → HUD 变 `Level 2/4` → …→ 清空第 4 关 → 中央 Victory 横幅、不再刷敌人、进度停在 4 关。可临时调 `LEVEL_COUNT=1` 或敌人低血量加速验证（仅测试，不改逻辑）。
2. **联机帧同步**：`--mode host` + `--mode client` 双端各一实例，跨多关游玩；观察无 `[CHECKSUM] MISMATCH`；退出后 diff 落盘的 `checksum_log_server.txt` / `checksum_log.txt`。
3. **地图固定**：多次开局验证障碍/出生点一致（同一 `LEVEL_MAP_SEED`）。

## 风险与取舍
- 推荐单固定图：障碍仅 wave1 物化一次、换关不重建，A* 可通行性缓存（`astar_work.walkable`)不失效 → 无穿墙风险；改动集中在"停波+胜利"，几乎不动实体创建路径，checksum 风险最低。
- **（本期不做，后续可选）每关新地图**：需每关 `spawn_obstacles_from_layout` + 障碍销毁/重建，且 **A* 可通行性缓存会失效导致敌人穿墙**（wave_system 代码明示此坑），并需给 MAP_RELOAD/loading 扩充障碍实体同步或双端同 seed 确定性重建，改动与回归面显著更大。
